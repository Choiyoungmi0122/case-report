# 실험용 Write 의 CARE 준수 점검 v1

- 기준: CARE guidelines for case reports: explanation and elaboration document (Riley DS et al., J Clin Epidemiol 2017;89:218–235). 13개 항목의 체크리스트 설명과 각 항목의 Explanation 을 읽고 대조했다.
- 점검일: 2026-10-10. 대상: `backend/src/studyWrite/careItems.ts`(항목표·쓰기 규칙), SW-Q2·SW-D·SW-C·SW-R 프롬프트, Word 내보내기.
- 결론부터: **점검 전에는 "엄격히" 지키지 않았다.** CARE에 없는 세부 항목을 만들었고(6b), CARE 설명서의 섹션별 요구(타임라인은 표, 이상반응 유무 명시, 서론 끝의 요약, 한약·침의 기술 수준 등)가 프롬프트에 없었다. 아래 "고친 것"을 반영한 뒤에는 체크리스트 문장과 항목 설명을 코드 한 곳(`careItems.ts`)에서 쓰고, 모든 체인이 그것을 받는다.

## 1. 먼저 분명히 할 것: 필수·선택

CARE 체크리스트에는 필수·선택 구분이 **없다.** 13개 항목(세부 항목 포함)이 모두 체크리스트 항목이다. 지금 시스템의 "필수/선택"은 연구실에서 만든 구분표를 옮긴 것이고, 질문 우선순위와 화면 표시에만 쓴다. 코드 주석과 프롬프트에 그렇게 적었다. 논문에 쓸 때도 "CARE의 필수 항목"이 아니라 "연구진이 정한 우선 항목"으로 써야 한다.

## 3. 원칙 충돌과 해소

- **P3(기록 부재 ≠ 없음) vs CARE 10d(이상반응 유무를 반드시 명시)**: "없었다"는 기록에 그렇게 적혀 있을 때만 쓰고, 언급이 없으면 "기록에 언급이 없다"로 쓴다. 두 요구를 모두 만족한다.
- **P5(효과 단정 금지) vs CARE 11c(인과 평가)**: 시간 관계와 관찰된 변화를 적고, 우연 가능성과 단일 사례의 한계를 명시한다. CARE 설명서도 "chance association을 배제할 수 없다"를 요구한다.
- **날짜**: CARE 설명서 Table 2(HIPAA 식별자)는 생년월일·사망일·입퇴원일을 식별 정보로 본다. 사용자 결정(2026-10-10)으로 실험용 Write는 날짜를 가리지 않는다. 초안 단계에서는 날짜가 필요하고, 투고용으로 바꿀 때는 "치료 N주째" 같은 상대 날짜로 바꾸는 것이 CARE·저널 요구에 맞는다. 최종 수정 단계에서 저자가 판단할 일이며 시스템이 강제하지 않는다.

## 4. 아직 지키지 못하는 것

- **문헌(4, 11b)**: 시스템은 문헌을 찾지 않는다. "[문헌 보완 필요]" 자리만 남긴다.
- **그림·표의 타임라인**: 표로는 되지만 그림(시각화)은 만들지 않는다.
- **한약 학명**: 기록에 학명이 없으면 쓰지 않는다. CARE/TIDieR 수준의 식물성 약 기술은 저자가 보완해야 한다.
- **저널별 요구**(초록 형식, 동의서 양식)는 다루지 않는다.
- **SW-C 점검은 모델 판단**이라 CARE 준수를 보장하지 않는다. 참여자가 확인하도록 보여 줄 뿐이다.

## 5. 샘플에서 확인 (2026-10-10, EQ008)

- 타임라인: 18개 "날짜 | 사건" 행으로 생성, Word 에서 2열 표로 변환. 처음에는 기록 전문에 방문 날짜가 없어 연도를 2024로 추정했다 → 기록 전문 머리글에 방문 날짜·구분(초진/재진)을 넣고 "연도 추정 금지"를 규칙에 넣었다.
- 추적 관찰: 척도 변화, HRV, 순응도 확인 방법(진술·약봉투·잔량), 이상반응 문장(안와부 멍 외 특이 이상반응 보고되지 않음)이 들어갔다.
- 서론: 보고 이유 → 핵심 메시지 → "[문헌 보완 필요]" → "이 증례보고는 CARE 지침에 따라 작성되었다."

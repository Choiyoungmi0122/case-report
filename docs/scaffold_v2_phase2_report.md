검증 중 추가 수정 2건(F단계):
- **실험용 Scaffold 케이스의 섹션 조회에서 적정성 검토 LLM 호출 제거.** V2(studyMode)에서는 공개 뒤 첫 조회 때 캐시 해시가 맞지 않아 gpt-4.1 검토가 새로 돌았다(약 4초 지연, 세션 중 LLM 1회, 참가자별로 다른 산출물 저장). 실험 화면은 이 검토를 쓰지 않으므로 고정 결과에 든 검토만 돌려주도록 바꿨고, 재검증에서 LLM 호출 0건을 확인했다. 공개 직후 잠깐 "초안이 없습니다"가 보이던 현상도 이 지연이 원인이었다.
- 학습 기록 화면과 Word 내보내기의 회고 소제목을 V2 문항으로 맞췄다.

## 7. 알려진 제한과 위험 요소

- **공개 전 데이터 노출 경로**: `careElementMap`은 공개 전 응답에 포함되고, `GET /api/cases/:id`·`/summary`는 초안을 그대로 돌려준다. 화면에서는 보이지 않으며 개발자 도구로만 접근 가능. 연구자 입회 환경을 전제로 남겨 두었다.
- **회고 문항 의미 변화**: `changedJudgment`·`missingInDraft`가 V1과 다른 질문의 답이다. 분석은 `scaffoldVersion`으로 나눠야 한다.
- **메모 회차는 사용자 지정**: 직접 메모의 회차를 사용자가 고르지 않으면 미지정으로 남는다. 자동 추정은 의도적으로 하지 않았다.
- **폭 조절 상태는 브라우저별**: 다른 기기·브라우저에서는 기본 배치로 시작한다.
- **공개 직후 로딩**: F단계 수정으로 LLM 지연은 사라졌지만, 서버 응답이 느리면 "AI 초안을 불러오는 중입니다…"가 잠깐 보이고 2초 간격으로 최대 3번 다시 불러온다.
- **단일 인스턴스 가정**: 케이스별 쓰기 직렬화가 프로세스 메모리 큐라 백엔드 인스턴스가 하나여야 한다(V1과 같음).
- **같은 기기에서 V1·V2 진입을 오갈 때**: 참가자 코드는 공유 저장소에 남고 세션 id만 분리된다. 코드가 바뀌면 세션이 초기화된다.
- **다른 세션의 병행 작업**: 같은 저장소에서 Write 모드 작업이 진행 중이다(미추적 파일 2개가 현재 `tsc` 오류를 낸다). V2 커밋과 섞이지 않게 분리해 두었고, 배포 전에는 그쪽 작업이 정리된 상태인지 확인이 필요하다.

# CARE 하위 요소 목록 v1 (초안, 2026-10-12)

- 목적: 실험용 Write 의 CARE 점검을 "항목 있음/없음"에서 "항목 안의 하위 요소가 어디까지 들어갔나"로 세분한다. 논문에서는 9b(시행 방법)가 "한약 처방명은 있는데 1첩 용량과 복용법이 없다" 식으로 부분만 채워지는 일이 많아서, 항목 하나를 있음으로 판정하면 빠진 부분이 보이지 않는다.
- 상태: 2026-10-12 사용자 결정으로 **네 섹션(환자 정보, 진단 평가, 치료 개입, 추적 관찰 및 결과)에 먼저 적용했고, 같은 날 나머지 여덟 섹션에도 적용했다.** 필수·선택 구분은 이 문서 그대로다. 적용 방식은 맨 아래 "9. 적용"에 있다.
- 기준 항목: `backend/src/studyWrite/careItems.ts` 의 `CARE_ITEMS_BY_SECTION` (연구실 CARE 필수·선택 구분표). 항목 번호와 필수·선택은 그대로 두고, 그 아래에 하위 요소만 단다.
- 범위: 모든 섹션. 치료 개입, 추적 관찰 및 결과, 진단 평가, 환자 정보를 가장 자세히 나눴다.

## 출처 표시

| 표시 | 출처 |
|---|---|
| CARE | CARE 체크리스트(2013)와 설명 문서(Riley 등, J Clin Epidemiol 2017). 항목 설명 문장을 요소 단위로 나눴다 |
| STRICTA n | 침 임상연구 보고 기준 STRICTA 2010(MacPherson 등). 1a~5 항목 번호. 6(대조군)은 증례보고에 해당하지 않아 뺐다 |
| CHM | CONSORT 한약 복합처방 확장안 2017(Cheng 등, Ann Intern Med). 중재 항목(5)의 처방 기술 요소 |
| 국내 | 국내 한의 학술지 증례보고 5편의 관례 (`docs/case_report_style_basis_v1.md`) |
| 준용 | 전용 보고 기준을 이 문서에 쓰지 않아, 가까운 기준(주로 STRICTA)을 빌려 온 것 |

CARE 표시 요소는 2026-10-12 CARE 설명 문서 원문 PDF(사용자 제공)와 대조했다. 그 결과 9b-H9 에 사용 부위(원문 Table 3), 10d-2 에 빈도와 환자의 표현(10d 설명)을 더했다. STRICTA, CHM 의 세부 문구는 아직 원문과 대조하지 않았다. 뜸·부항은 별도의 보고 확장안이 있다고 알려져 있으나 확인하지 못해서 "준용"으로 두었다.

## 구조와 판정 규칙

```
섹션 (예: 치료 개입)
└ CARE 항목 (예: 9b 시행 방법, 필수)
  └ 하위 요소 묶음 (예: 한약)  ← 적용 조건: 기록에 한약 처방이 있을 때
    └ 하위 요소 (예: 9b-H2 구성 약재와 1첩 용량, 필수)
```

- **하위 요소의 필수**: 그 개입이 이 사례에 있을 때, 빠지면 다른 임상의가 따라 할 수 없거나 경과를 읽을 수 없는 요소다. **선택**은 있으면 좋고 없어도 보고가 성립하는 요소다.
- **적용 조건**: 묶음마다 붙는다. 이 사례에 그 개입이 없으면 묶음 전체를 "해당 없음"으로 두고 준수율 계산에서 뺀다. 개입은 있는데 요소가 초안에 없으면 "없음"이다.
- **항목 판정**: 필수 하위 요소가 모두 있으면 "있음", 일부만 있으면 "일부", 하나도 없으면 "없음". "일부"는 지금 없는 상태라 새로 만들어야 한다.
- 하위 요소 ID 는 `항목번호-묶음글자번호` 다. 묶음 글자는 H 한약, A 침·전침, P 약침, M 뜸, C 부항, W 양약, L 생활 지도·상담, O 그 밖의 치료(추나·물리치료 등)다. 묶음이 없는 항목은 `항목번호-번호` 다.

## 7. 점검 방식을 바꾸면 달라지는 것

### 적용 판정 (어느 묶음을 볼지)

- 권장: **코드가 먼저 후보를 고르고, 점검 모델이 확정한다.** 코드는 기록과 9a 초안에서 낱말을 찾는다(탕·산·환·음 → 한약, 침·전침 → 침, 약침 → 약침, 뜸·구 → 뜸, 부항 → 부항, 등록된 양약 이름 → 양약). 모델은 후보마다 "이 사례에 있음/없음"을 이유와 함께 낸다.
- 화면에서 사용자가 묶음을 켜고 끌 수 있게 한다. 잘못 고른 묶음 때문에 준수율이 떨어지는 일을 막는다.

### 준수율

- 지금(v1): 항목 단위. 있음 + 해당 없음 / 전체 항목.
- 바꾸면(v2): 항목 단위 준수율은 그대로 두고, **하위 요소 준수율을 따로** 보여 준다. 항목 판정에는 "일부"가 새로 생긴다.
- 이유: 항목 단위 값은 이미 돌린 사례(임교수 테스트 6 등)와 견줄 수 있어야 한다. 하위 요소 단위로 바꾸면 같은 초안도 준수율이 크게 낮아 보인다.
- 점검 결과에 체크리스트 버전(`care-checklist:v1` / `v2`)을 같이 저장한다.

### 비용과 질문

- SW-C 출력이 항목 수십 개에서 하위 요소 백여 개로 늘어난다. 묶음은 적용되는 것만 넣는다. 사례 하나의 점검 비용은 지금의 두 배쯤으로 추정한다(측정 전).
- "이 정보 입력하기"의 AI 질문(SW-Q3)이 항목이 아닌 하위 요소를 받으면 질문이 더 좁아진다. 예를 들어 9b 전체 대신 "9b-H4 복용법"만 묻는다.

### 화면

- CARE 점검 탭의 항목 카드 아래에 하위 요소를 접어 둔다. "일부" 항목은 펼친 채로 보여 주고, 빠진 하위 요소마다 "이 정보 입력하기"를 단다.

## 8. 정해야 할 것

1. **필수·선택 구분**: 위 표에서 바꿀 것. 특히 9b-A2 침 규격, 6-1 활력징후, 9b-W3 양약 유지 여부를 필수로 둔 것이 실험 참여자(전문 한의사)의 기록 습관에 맞는지.
2. **준수율 표시**: 항목 단위를 주로 두고 하위 요소를 보조로 둘지, 하위 요소 단위로 바꿀지.
3. **범위**: 처음에는 치료 개입, 추적 관찰, 진단 평가, 환자 정보 네 섹션에만 붙일지, 전 섹션에 붙일지.
4. **원문 대조**: STRICTA, CONSORT 한약 확장안 원문 PDF 를 주면 출처 문구를 맞춘다. 뜸·부항 보고 기준이 있으면 그것도.
5. **Scaffold 적용 여부**: 이 문서는 실험용 Write 만 대상으로 했다. Scaffold 의 CARE 기준(`config/careSectionRubric.ts`)은 다른 세션이 맡고 있어 건드리지 않는다.

## 9. 적용 (2026-10-12)

- 코드: 정의 `backend/src/studyWrite/careSubElements.ts`, 점검 `backend/src/studyWrite/drafting.ts` 의 `runCareCheck`, 프롬프트 SW-C v3, 화면 CARE 점검 탭.
- 점검 호출은 늘리지 않았다. SW-C 한 번에 항목 판정과 하위 요소 판정(subItems)을 같이 받는다. 항목 판정은 v1 과 같은 기준이다.
- 저장: 점검 결과에 `checklistVersion: care-checklist:v2`, 항목마다 `subItems`, 치료 개입에는 `modalities`(점검한 개입 묶음과 찾지 못해 점검하지 않은 묶음).
- 준수율: 항목 단위 준수율은 그대로 두었다. 하위 요소 준수율은 따로 보여 주며, "해당 없음"과 "판정 없음"을 분모에서 뺀다. 항목이 "있음"인데 해당되는 필수 하위 요소가 빠졌으면 화면에 "일부"로 보인다. 저장된 항목 판정은 바꾸지 않는다.
- 개입 묶음 고르기: 기록·답변·초안에서 낱말로 고른다. 한약은 "○○탕", "○○산가감"처럼 꼴이 분명한 것과 용어 사전의 처방명 87개로 찾는다. "그리고", "처음"처럼 낱말 끝이 같은 말은 잡지 않는다.
- 조건이 붙은 요소: 모델이 조건 충족 여부(conditionMet)를 따로 낸다. 거짓이면 코드가 해당 없음으로 둔다. 낱말로 확실히 가릴 수 있는 세 요소(5a-5 인종·민족, 5c-8 유전 정보, 9b-A6 전침 조건)는 코드가 정한다. 같은 초안에서 gpt-4.1-mini 가 전침 여부를 다르게 판정한 일이 있었다.
- "이 정보 입력하기": 하위 요소 판정이 있는 항목은 버튼이 하위 요소마다 붙는다. AI 질문(SW-Q3)이 그 요소 하나만 묻는다. 예: 9b-A3 에서 "각 내원 때마다 침을 꽂아 둔 시간은 몇 분이었는지".
- "CARE 다시 점검" 버튼: 초안은 그대로 두고 점검만 다시 한다. 하위 요소 기준 전에 점검한 섹션에는 그 사실을 함께 보여 준다.
- 같은 날 나머지 여덟 섹션(제목, 초록, 서론, 임상 소견, 타임라인, 고찰, 환자 관점, 동의)에도 붙였다. 이제 모든 섹션의 점검이 v2 다.
- 조건이 붙은 요소는 목록에서 conditionMet 을 반드시 적게 했다. 처음에는 9a-2·7-5(다른 의료진의 치료)에서 모델이 조건을 판정하지 않고 "없음"으로 두었는데, 이 표시를 넣은 뒤 "해당 없음"으로 맞게 나왔다.

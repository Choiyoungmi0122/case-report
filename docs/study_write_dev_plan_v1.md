# 실험용 Write 개발 계획 v1 (확인용 초안)

- 작성: 2026-10-10. 사용자가 말한 요구를 정리한 것이며, 확인받기 전까지 코드는 바꾸지 않는다.
- 진입: 첫 화면 "실험용 Write 시작" → `/study/write` (실험번호 입력) → 이 계획의 흐름.
- 원칙: 실험용 Scaffold(`/study/scaffold/...`)는 손대지 않는다. 공용 파일(`App.tsx`, `api.ts`, `cases.ts`)을 고칠 때는 Scaffold 경로의 동작이 바뀌지 않게 하고, 고친 뒤 Scaffold를 한 번 돌려 확인한다.

## 1. 한 줄 요약

진료 기록(직접 입력, 또는 xlsx·docx·pdf 업로드)을 넣으면 시스템이 기록을 CARE 섹션별로 나누고, 정해진 횟수 안에서 질문과 답변을 주고받은 뒤, 전체 섹션의 초안을 쓴다. 답변은 최종 제출 전까지 고칠 수 있다.

## 2. 사용자가 말한 요구

| 번호 | 요구 | 계획서의 해석 |
|---|---|---|
| R1 | EMR 내용, 엑셀, docx, pdf 업로드 | 네 가지 입력 경로. 업로드 파일은 서버에서 텍스트로 바꾼 뒤 지금의 방문별 기록 형태로 넣는다 |
| R2 | Scaffold처럼 일단 다 나눠서 들어감 | 지금 Write 모드의 분석(기록 분할·태깅 → 근거 문장 → 섹션별 초안)을 그대로 쓴다 |
| R3 | 몇 번의 질문과 답변으로 전체 섹션 초안 작성 | 질문을 한 번에 다 보여 주지 않고 **회차(round)** 로 묶어서 묻는다. 횟수·개수 상한을 정한다 |
| R4 | 답변 횟수는 사람이 기분 나쁘지 않고 번거롭지 않은 범위. 논문 근거로 정함 | 상한의 근거를 문헌에서 찾아 문서로 남긴다 (아래 5절) |
| R5 | 최종 제출 전에 답변 수정 가능 | 답변 목록 화면에서 고칠 수 있고, 고치면 관련 섹션 초안을 다시 쓴다 |

## 3. 지금 있는 것과 새로 만들 것

### 이미 있어서 그대로 쓰는 것 (일반 Write 모드)

- 방문별 기록 입력 화면, 분석 파이프라인(CHAIN1 분할·태깅, CHAIN2 평가, CHAIN3 섹션 초안, CHAIN4 부족 정보, CHAIN5 질문 생성, CHAIN6 답변 반영, CHAIN7 최종 원고)
- 공통 질문(`commonQuestionSets`)과 답변 저장(`/common-questions/answer`), 답변 되돌리기(`undo-last-answer`)
- 섹션 화면, 최종 원고 화면, Word 내보내기
- xlsx 읽기(`xlsx`), docx 읽기(`mammoth`), pdf 읽기(`pdf-parse`) 라이브러리. xlsx는 타임라인 가져오기에 이미 쓰고 있다
- 실험용 경로(`/study/write/...`)와 실험번호, 연구용 내보내기, 행동 로그

### 새로 만들 것

| 구분 | 내용 |
|---|---|
| N1 파일 업로드 | 입력 화면에 "파일 올리기" 추가. xlsx(행 = 방문 또는 열 = 날짜/기록), docx, pdf → 텍스트 추출 → 방문 단위로 나누기(날짜 패턴으로 자르고, 못 나누면 한 덩어리로) → 사용자가 확인·수정한 뒤 분석 시작 |
| N2 질문 회차 | 생성된 질문을 중요도 순으로 정렬해 회차마다 N개만 보여 준다. 답을 다 하거나 "모름/해당 없음"을 고르면 다음 회차. 상한에 닿으면 질문을 멈추고 초안으로 간다 |
| N3 답변 보관함 | 질문·답변 목록 화면. 제출 전까지 답을 고칠 수 있다. 고치면 그 답이 들어간 섹션만 다시 쓴다(CHAIN6). 이전 답과 초안은 이력으로 남긴다 |
| N4 제출 | "최종 제출" 버튼. 제출하면 답변이 잠기고 최종 원고(CHAIN7)와 Word가 만들어진다. 제출 전에는 언제든 답을 고칠 수 있다 |
| N5 기록 | 회차 수, 질문 수, 답한 수, 건너뛴 수, 답 수정 횟수, 각 단계 시각을 연구용 내보내기에 넣는다 |

## 4. 화면 흐름 (초안)

```
실험번호 입력
  → 기록 넣기 (직접 입력 / 파일 올리기 → 방문별로 나뉜 결과 확인)
  → 분석 시작 (기록 분할, 근거 문장, 섹션별 1차 초안)
  → 질문 1회차 (N개) → 답변
  → [질문 2회차 … 상한까지]
  → 전체 섹션 초안 보기 (답변이 반영된 상태)
  → 답변 보관함에서 답 고치기 (고친 섹션만 다시 씀)  ← 제출 전까지 반복 가능
  → 최종 제출 → 최종 원고 → Word
```

Scaffold와 다른 점: 참여자가 직접 초안을 쓰지 않는다. AI 초안 공개 전 판단, 문장 표시, 비교 정리는 없다.

## 5. 질문 상한: 근거를 어떻게 정할 것인가

- 사용자 요구는 "사람이 기분 나쁘지 않고 번거롭지 않은 횟수"다. 이것은 설문 피로(survey fatigue), 대화형 시스템의 질문 부담, 임상 문서화 부담 쪽 문헌에서 근거를 찾는다.
- 진행 방법: 문헌을 검색해 (1) 한 번에 보여 줄 질문 수, (2) 총 회차, (3) 총 질문 수, (4) 질문 하나의 길이·형식(객관식 우선, 서술형 최소)에 대한 근거를 `docs/question_budget_basis_v1.md`에 정리한다. 근거가 약한 항목은 "약함"으로 표시하고, 1차 실험 뒤 조정한다.
- **정한 값(2026-10-10, `question_budget_basis_v1.md`):** 최대 3회차 × 3개, 기본 6개·최대 9개. 1회차는 사례 전체 질문(기여·초점·동의), 2회차는 기록의 빈칸, 3회차는 필요할 때만. 진행 표시와 건너뛰기 버튼, 10분 안내.
- 지금 CHAIN5가 만드는 질문 수는 상한이 없다. 상한을 넘으면 중요도(필수 CARE 항목 > 선택 항목, 여러 섹션에 걸친 질문 > 한 섹션 질문)로 잘라 낸다.

## 6. 데이터 (DB)

- 새 컬렉션은 만들지 않는다. `cases` 문서에 아래를 더한다. 마이그레이션 불필요.
  - `studyWrite`: `{ inputSource: 'manual' | 'xlsx' | 'docx' | 'pdf', uploadedFileName, rounds: [{ roundNo, questions: [{ id, text, targetSectionIds, priority, answer, answerStatus: 'answered' | 'skipped' | 'pending', answeredAt, editHistory: [...] }], startedAt, completedAt }], submittedAt, questionBudget: { maxRounds, perRound, maxTotal } }`
- 업로드한 원본 파일은 저장하지 않는다. 추출한 텍스트만 저장한다(지금 타임라인 가져오기와 같은 원칙).

## 7. 단계별 일정 (확인 뒤 시작)

| 단계 | 내용 | 산출물 | 예상 |
|---|---|---|---|
| 0 | 질문 상한 근거 문헌 조사 | `question_budget_basis_v1.md` | 반나절 |
| 1 | 파일 업로드와 방문 나누기 (N1) | 입력 화면, 업로드 API, 나누기 규칙 테스트 | 1일 |
| 2 | 질문 회차와 상한 (N2) | 회차 화면, 상한 로직, 우선순위 | 1일 |
| 3 | 답변 보관함과 수정 → 재작성 (N3) | 보관함 화면, 수정 이력 | 1일 |
| 4 | 최종 제출과 잠금 (N4), 연구용 기록 (N5) | 제출 흐름, 내보내기 항목 | 반나절 |
| 5 | 끝까지 돌려 보기, Scaffold 영향 확인, 커밋 | 점검 기록 | 반나절 |

합쳐서 4~5일. 단계마다 커밋하고, 각 단계 끝에 확인받는다.

## 8. 확인이 필요한 것

1. **엑셀 양식**: 참여자가 올릴 엑셀이 정해진 양식(예: 날짜 | 기록)인가, 아니면 병원 EMR에서 받은 임의 양식인가? 임의 양식이면 열 고르기 화면이 필요하다.
2. **PDF 종류**: 글자가 있는 PDF만 지원해도 되나, 스캔 이미지(OCR 필요)도 있나?
3. **비식별**: 업로드한 실제 기록이면 비식별 처리를 거친다(지금 Write와 같음). 가상환자 기록만 쓸 거면 끄는 쪽이 낫다. 어느 쪽인가?
4. **질문 형식**: 서술형 답만 받을지, 객관식(예: 있음/없음/모름)을 섞을지. 번거로움을 줄이려면 객관식을 권한다.
5. **임시 상한값**(2회차 × 5개, 총 10개)으로 시작해도 되나? 근거 조사 뒤 바꾼다.
6. **대상 섹션**: 전체 13개 섹션 모두 초안을 쓰는가, 아니면 기록으로 쓸 수 있는 섹션(환자 정보, 임상 소견, 타임라인, 진단 평가, 치료 개입, 추적 관찰)만 쓰고 서론·고찰은 틀만 주는가?
7. **답변 수정 시 재작성 범위**: 고친 답이 들어간 섹션만 다시 쓰는 것으로 가도 되나? (전체 재작성은 느리고 비용이 큼)
8. **이 Write 실험의 참가자와 측정**: Scaffold 실험과 같은 참가자인가, 다른 집단인가? 보려는 것(소요 시간, 질문 부담, 초안 만족도 등)이 정해져야 N5의 기록 항목을 확정할 수 있다.

## 9. 범위 밖 (이번에는 안 함)

- 참여자가 직접 초안을 쓰는 단계, AI 초안 문장 표시, 비교 정리 (Scaffold 전용)
- 원본 파일 저장, 스캔 PDF OCR (2번 답에 따라)
- 서론·고찰의 문헌 검색

## 11. 확정 흐름 (v2)

```
① 시작 화면 (실험번호)
② 기록 넣기: 직접 입력 / xlsx(열 고르기) / docx → 방문별 나눔 확인
③ 비식별 → 전문용어 확인 → 분석 (CARE 섹션별 배정, 1차 초안을 뒤에서 준비)
④ 질의응답: 채팅창만 보임. 글(초안)은 보이지 않음.
   - 횟수는 ⑤ 근거 문서에서 정한 상한
   - 사례 전체에 대한 질문 (이 증례의 기여, 가치, 초점 등) + 기록에 없어 초안을 못 쓰는 것
   - 주고받은 내용은 수정 가능. 이것을 바탕으로 초안을 만들어 감
⑤ 전체 초안 생성 (모든 CARE 섹션)
⑥ 섹션별 화면: 초안 옆에 채팅창. 채팅으로 그 섹션을 고침
   - CARE 필수 요소·선택 요소 중 빠진 것을 알려 줌 (질의응답에서 못 채웠을 수 있으므로)
   - 섹션마다 표(xlsx)·그림 올리기, 표·그림 제목 넣기
⑦ 최종 수정: 전체 글을 직접 편집
⑧ Word 내보내기 (표·그림 포함)
```

## 12. 새로 커진 범위

- 섹션별 채팅 수정(⑥)과 표·그림 업로드는 v1에 없던 것이다. 그림 저장소, Word에 표·그림 넣기, 캡션·번호 매기기가 추가된다.
- 일정은 v1의 4~5일에서 8~10일로 늘어난다. 단계별 확인은 그대로.

## 13. 2026-10-10 추가 확인 (사용자 답)

| 항목 | 답 |

| 전문용어 확인 | 지금 Write의 화면 그대로, 질의응답 전에 |

### 기록 항목(N5) 확정

유용성·효율성을 보는 것이므로 아래를 남긴다.
- 단계별 소요 시간: 업로드~분석, 질의응답, 초안 생성, 섹션 수정, 최종 수정, 내보내기
- 질의응답: 질문 수, 답한 수, 건너뛴 수, 질문별 답 시간, 답 수정 횟수
- 섹션 수정: 섹션별 채팅 지시 수, 재작성 수, 직접 편집 글자 수(초안 대비 변경 비율), 표·그림 첨부 수
- CARE 빠진 요소 알림: 알림 수, 그 뒤 채워진 수
- 사후: 유용성·효율성 설문과 인터뷰(기능별 필요/불필요)는 별도 문서로

## 14. 참가자 (2026-10-10 확인)

- Scaffold 전문가 평가(다음 주)에 참여하는 **같은 전문가 약 10명**이 Write도 본다.
- 모두 한의과이며 과가 다르다: 침구과, 내과, 안이비인후피부과(오관과), 소아과, 신경정신과, 부인과.
- 따라서 Write는 특정 과의 사례에 맞춰서는 안 된다. CARE 섹션 배정, 질문 생성, 빠진 요소 알림이 과와 무관하게 동작해야 하고, 고정 가상환자(신경정신과)만으로는 다른 과 전문가가 유용성을 판단하기 어렵다. **각자 자기 과의 기록(비식별 처리)을 올리는 경우**를 기본으로 설계한다. 열 고르기(1번 답)가 이 때문에 더 중요하다.
- 한 세션에서 Scaffold 시연·인터뷰와 Write 사용을 모두 하므로 시간 배분이 필요하다 (아래 확인 필요).

## 15. 2026-10-10 확정

- 전문가는 **자기 환자 기록**을 올린다 → 비식별 켬. 연구자는 전문가 소속 기관의 규정 확인을 세션 전에 끝낸다.
- 세션은 **70분**. 배분 초안: Scaffold 시연·인터뷰 25분, Write 사용 35분(업로드 5, 질의응답 10, 초안·섹션 수정 15, 최종·Word 5), 설문·인터뷰 10분.
- 질문 상한 **3회차 × 3개(기본 6, 최대 9)** 확정.
- **AI 체이닝:** 초안 생성과 질문 생성은 지금 Write의 CHAIN1~7처럼 단계별 체인으로 만든다. 새 체인(가칭): SW-Q1 사례 전체 질문 생성(기록 요약 → 기여·초점·동의 질문 3개), SW-Q2 빈칸 질문 생성(CARE 배정 결과 → 필수·선택 빈칸 → 우선순위 → 3개), SW-D 답 반영 섹션 초안, SW-R 섹션별 채팅 수정(지시 + 기록 근거 확인 → 재작성 + 기록 외 표시), SW-C CARE 빠진 요소 점검. 프롬프트는 `backend/src/llm/prompts/studyWrite_*.ts`에 두고 버전을 적는다.
